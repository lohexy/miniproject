# Інструкція з тестування (Testing Guide)

Цей документ описує стратегію тестування, налаштування середовища та інструкції для запуску тестів у проєкті. Проєкт використовує фреймворк `xUnit` для автоматизованого тестування.

## Як запустити тести

Для запуску всіх тестів (Unit та Integration) відкрийте термінал у кореневій папці проєкту та виконайте команду:
```bash
dotnet test
```

## Як зібрати метрику покриття коду (Code Coverage)

Ми використовуємо пакет `coverlet.msbuild` для аналізу покриття коду. Щоб згенерувати звіт у терміналі, виконайте:
```bash
dotnet test /p:CollectCoverage=true
```

Щоб згенерувати візуальний HTML-звіт (за наявності встановленого `ReportGenerator`):
```bash
dotnet test /p:CollectCoverage=true /p:CoverletOutputFormat=opencover
reportgenerator -reports:"/coverage.opencover.xml" -targetdir:"coverage-report" -reporttypes:Html
```

## Категорії тестів та покриті сценарії

У нашому проєкті тести розділені на три основні категорії:

1. Application Layer (Use Cases):
   - Успішне додавання нових задач.
   - Валідація унікальності назви (включаючи нечутливість до регістру та пробілів).
   - Зміна статусів та перевірка логіки (наприклад, неможливість завершити прострочену задачу).
   - Правильний підрахунок аналітики (`GetAnalytics`).
   - Фільтрація списку задач.

2. Domain Layer:
   - Робота `TaskFactory` (правильне створення об'єктів).
   - Обробка прикордонних значень (наприклад, від'ємна кількість днів до дедлайну).
   - Генерація унікальних `Guid` для нових задач.

3. Infrastructure Layer (Fault Handling):
   - Збереження та завантаження даних у форматі JSON.
   - Підтримка кодувань (UTF-8, емодзі, спецсимволи).
   - Відмовостійкість: автоматичне відновлення даних з `.csv` бекапу у разі пошкодження основного JSON-файлу.
   - Безпечна реакція системи на порожні або повністю пошкоджені файли.
