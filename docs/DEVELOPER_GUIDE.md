# 🛠 Посібник розробника

Цей документ описує архітектуру проєкту, використані патерни та правила розширення системи.

## Архітектура
Проєкт побудований за принципами Clean Architecture (або Onion/N-Tier) та розділений на 4 основні шари:
1. Domain (`src/Domain`): Ядро системи. Містить сутності (`UserTask`, `Project`), перерахування (`TaskStatus`, `TaskPriority`) та доменні винятки (`TaskDomainException`). Не залежить від жодного іншого шару.
2. Application (`src/Application`): Містить бізнес-логіку. Клас `TaskService` відповідає за створення задач, валідацію, зміну статусів та аналітику (LINQ).
3. Infrastructure (`src/Infrastructure`): Робота з файловою системою (I/O). Реалізує збереження у JSON та механізм Fallback-відновлення з CSV.
4. ConsoleApp (`src/ConsoleApp`): Тонкий шар представлення (UI). Відповідає виключно за зчитування вводу з консолі та вивід тексту.

## Використані патерни проєктування
* Factory Method: Реалізовано у класі `TaskFactory` (шар Domain) для інкапсуляції логіки створення задач та правильного розрахунку дедлайнів на основі переданих параметрів.
* Repository Pattern: Реалізовано у класі `JsonTaskRepository`. Ізолює бізнес-логіку від деталей роботи з `System.Text.Json` та файловою системою.
* Resilience (Fallback): При пошкодженні JSON-файлу (`FormatException` або `JsonException`), репозиторій автоматично перемикається на читання даних із резервного файлу `.csv`.

## Тестування
Проєкт покритий автоматизованими тестами (фреймворк `xUnit`). 
Для запуску тестів виконайте: `dotnet test`.
Для перевірки покриття (Coverage): `dotnet test /p:CollectCoverage=true`.

## Як додати новий формат збереження (наприклад, XML)
1. Створіть інтерфейс `ITaskRepository` у шарі Domain.
2. Зробіть так, щоб `JsonTaskRepository` реалізовував його.
3. Створіть новий клас `XmlTaskRepository : ITaskRepository` в Infrastructure.
4. Підмініть реалізацію в `Program.cs` при ініціалізації.
