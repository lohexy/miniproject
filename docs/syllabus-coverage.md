# Матриця покриття курсу (Syllabus Coverage)

Цей документ демонструє, як ключові теми навчального курсу були інтегровані у фінальний реліз проєкту.

## 1. Обов'язково використано (Core Topics)
* Основи ООП: Реалізовано глибоку інкапсуляцію (захист полів, використання властивостей з `private set` у майбутньому масштабуванні), наслідування (ієрархія доменних винятків, як-от `DuplicateTaskTitleException`).
* Абстракції, поліморфізм, інтерфейси: Виділено інтерфейс `IDataStore<UserTask>`, через який UI взаємодіє з даними, не знаючи про конкретну реалізацію (JSON чи бази даних).
* Generics, колекції, LINQ, делегати: * Широке використання `List<T>`.
  * Складна агрегація та групування за допомогою LINQ (метод `GetAnalytics`).
  * Використання делегатів (`Action<UserTask>`) для реалізації подій.
* Обробка помилок і persistence: Відмовостійке збереження у `tasks.json`. Кастомна обробка `JsonException` та `FormatException` із механізмом Fallback.
* SOLID: * SRP: `ConsoleMenu` відповідає лише за UI, `TaskService` — за бізнес-логіку.
  * DIP: Робота через абстракції (Repository).
* Патерни: У проєкті імплементовано *Factory Method* (`TaskFactory`), *Repository* (`JsonTaskRepository`), *Fallback* та *Observer*.
* UML: Архітектура проєкту проєктувалася на основі діаграм класів та Use Case діаграм (описано в попередніх звітах).
* Тестування: Проєкт повністю покритий автотестами на базі `xUnit` (53 тести, використання параметризованих тестів `[Theory]`, перевірка I/O збоїв, 86.5% Line Coverage).
* Рефакторинг: Проведено фінальний рефакторинг: усунуто "Magic Strings" (перехід на `enum`), розбито "God Object" класи, оптимізовано продуктивність LINQ-запитів.

## 2. Додаткові розширення для закриття прогалин у курсі (Advanced Features)
Для демонстрації глибшого розуміння курсу, на фінальному етапі в проєкті було свідомо задіяно такі 3 додаткові розширення:

1. Observer для повідомлень (через Делегати): У класі `JsonTaskRepository` реалізовано подію `public event Action<UserTask>? OnTaskAdded;`. Це класичний патерн Observer, який дозволяє підписуватися на події додавання нових задач (наприклад, для майбутньої системи аудит-логів або відправки сповіщень) без жорсткої прив'язки до UI.
2. Окремий аналітичний LINQ модуль:
   Логіку підрахунку статистики (завершених, прострочених, згрупованих за пріоритетом задач) винесено в окремий метод `GetAnalytics()`. Метод демонструє впевнене володіння агрегатними функціями (`GroupBy`, `Any`, `Count`).
3. Async batch import / export:
   Імплементовано механізм асинхронного пакетного збереження та відновлення даних (методи `SaveAsync` та `ImportFromCsvAsync`), які здатні обробляти сотні рядків без блокування основного потоку.
