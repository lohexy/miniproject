# Project Backlog: Task Management System

## ✅ Ітерація 1 (Lab 34): Архітектурний фундамент
* [x] Проєктування: Створення UML-діаграм класів та послідовності.
* [x] Інфраструктура: Налаштування Solution з розділенням на шари (Domain, Application, Infrastructure, Console).
* [x] Доменна модель: Реалізація класів `UserTask`, `User`, `Project`.
* [x] Vertical Slice: Реалізація базового додавання задачі та збереження в пам'яті.
* [x] CI: Налаштування GitHub Actions.

## Ітерація 2 (Lab 35): Логіка та збереження даних
* Persistence: Реалізація збереження та завантаження даних з JSON-файлів.
* LINQ: Створення системи фільтрації задач за статусом та пошук за ключовими словами.
* Розширення: Додавання складної логіки (наприклад, автоматичне пріоритезування) та впровадження патернів проєктування (напр. Factory або Strategy).

## Ітерація 3 (Lab 36): Якість та тести
* Unit Testing: Покриття доменної логіки тестами (мінімум 20 тестів).
* Integration Testing: Перевірка коректності збереження даних у файли.
* Fault Handling: Обробка помилок вводу та винятків при роботі з файловою системою.
* Quality Gate: Налаштування перевірки покриття коду (coverage) в CI.

## Ітерація 4 (Lab 37): Фіналізація та реліз
* Hardening: Виправлення знайдених багів та рефакторинг.
* Документація: Створення `USER_GUIDE.md` та `DEVELOPER_GUIDE.md`.
* Demo: Підготовка демонстраційного сценарію для захисту проєкту.
