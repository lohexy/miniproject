# Звіт: Ітерація 1 (Лабораторна робота №34)

## Мета ітерації
Створити архітектурний каркас проєкту, визначити основні сутності предметної області, реалізувати перший робочий сценарій ("вертикальний зріз") та налаштувати CI-пайплайн і тестування.

## Виконані завдання
1. Проєктування та документація:
   - Створено `vision.md` з описом концепції системи.
   - Сформовано `backlog.md` із переліком задач на всі ітерації.
   - Розроблено UML-діаграму класів (6+ сутностей) та діаграму послідовності (Sequence Diagram).
2. Архітектура та Доменна модель:
   - Створено Solution `miniproject.sln` із розділенням на шари: `Domain`, `Application`, `Infrastructure`, `Console`.
   - Реалізовано 6+ типів доменної моделі: `UserTask`, `Project`, `User`, `Category`, `TaskPriority`, `TaskStatus`.
   - Налаштовано `InMemoryTaskRepository` для тимчасового зберігання даних.
3. Вертикальний зріз та Консольний UI:
   - Реалізовано інтерактивне консольне меню для створення та перегляду задач.
   - Додано базову валідацію вводу користувача.

## Додаткові розширення 
У рамках цієї ітерації було реалізовано додаткові вимоги для "сильного проєкту":
- Factory Pattern: Створено `TaskFactory` для інкапсуляції логіки створення задач із дефолтними параметрами.
- Делегати (Action): Використано `Dictionary<string, Action>` для маршрутизації консольного меню замість громіздких конструкцій `switch/case`.
- IDisposable: Імплементовано в `InMemoryTaskRepository` для коректного очищення колекцій при завершенні роботи.
- Індексатори: Перевантажено індексатор `this[int index]` у класі `Project` для зручного доступу до списку задач.
- Підготовка до Observer: У репозиторії створено подію `event Action<UserTask>? OnTaskAdded`, яка сповіщає систему про нові задачі.

## Тестування та CI
- Написано 5 юніт-тестів (xUnit) для перевірки доменної логіки (дефолтні статуси, створення проєктів тощо).
- Налаштовано GitHub Actions (`ci.yml`) для автоматичної збірки (`dotnet build`) та запуску тестів (`dotnet test`) при кожному push.
